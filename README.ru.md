# genabot

[English](README.md) · **Русский**

Небольшой модераторский бот для Matrix (Synapse): удаляет сообщения по команде в комнате. Python, [matrix-nio](https://github.com/matrix-nio/matrix-nio), запускается в Docker.

## Команды

Префикс настраивается (`BOT_CMD`, по умолчанию `!genabot`). Команды выполняются только у тех, кто есть в `ALLOWED_INVITERS` (если список задан) и у кого в комнате уровень прав не ниже `MIN_LEVEL` (по умолчанию 50).

| Команда | Что делает |
|---|---|
| `!genabot help` | справка |
| `!genabot ping` | проверка, что бот жив |
| `!genabot del` | ответом на сообщение: удалить его |
| `!genabot purge [N] [from:КТО] [text:СЛОВО] [older:7d] [dry] [yes]` | удалить сообщения по фильтру |
| `!genabot purge all yes` | удалить **все** сообщения комнаты (всегда нужно `yes`; без других параметров) |
| `!genabot keep N [from:КТО] [text:СЛОВО] [dry] [yes]` | оставить последние N сообщений, более ранние удалить |

Параметры `purge`/`keep`:

- `N` — сколько последних подходящих сообщений (для `purge` без `N` нужен хотя бы один фильтр);
- `from:` — часть имени отправителя (`from:webhooks`, `from:@user`);
- `text:` — слово или фраза в тексте (фразу в кавычках: `text:"две фразы"`);
- `older:` — старше срока: `30m`, `12h`, `7d`, `2w` (только для `purge`);
- `room:!id:server` — чистить **другую комнату** (в том числе шифрованную) вместо текущей, см. «Шифрованные комнаты» ниже;
- `dry` — только посчитать, ничего не удаляя;
- `yes` — подтвердить удаление, если сообщений больше 20 (`CONFIRM_OVER`).

Примеры: `!genabot keep 100 dry`, `!genabot purge from:webhooks older:7d yes`, `!genabot purge 10`.

Удаление идёт обычным способом Matrix (redact): сообщение превращается в пустую «оболочку», которая остаётся в истории. Клиенты листают такие участки вхолостую, поэтому после больших чисток лучше физическое стирание (см. ниже).

По умолчанию бот отвечает по-английски; для русских ответов задайте `BOT_LANG=ru` в `.env`.

## Установка

1. Создайте учётку бота на сервере, например:

   ```bash
   register_new_matrix_user -c /etc/matrix-synapse/homeserver.yaml -u genabot -p 'ПАРОЛЬ' --no-admin http://localhost:8008
   ```

2. Скопируйте `.env.example` в `.env` и заполните `MATRIX_HOMESERVER`, `MATRIX_USER`, `MATRIX_PASSWORD`, `ALLOWED_INVITERS`.
3. Запустите:

   ```bash
   docker compose up -d --build
   ```

4. Пригласите бота в комнату и выдайте ему уровень модератора (50 и выше: так он сможет удалять чужие сообщения).

Токен бот получает сам при первом входе и хранит в `data/session.json` (права 600). Бот принимает приглашения только от `ALLOWED_INVITERS` (если пусто, от любого пользователя своего сервера).

## Шифрованные комнаты

В боте нет E2EE, поэтому команду, написанную в шифрованной комнате, он не прочитает. Пишите команду в любой **нешифрованной** комнате, где есть бот, и добавляйте `room:` с идентификатором нужной комнаты (Element: Настройки комнаты → Расширенные):

```
!genabot keep 100 room:!abc123:example.org dry
!genabot purge all yes room:!abc123:example.org
```

Условия: задан `ALLOWED_INVITERS`, включён `ADMIN_MODE=1`, бот состоит в целевой комнате и является там модератором, а вы состоите в ней и имеете уровень не ниже `MIN_LEVEL`. В шифрованных комнатах текст сообщений неизвестен, поэтому фильтр `text:` недоступен; используйте `N`, `from:`, `older:` или `all`.

## Ограничения

- Команды читаются только в **нешифрованных** комнатах (E2EE не реализован); шифрованные комнаты чистятся удалённо, см. выше.
- Без админского режима бот видит историю только с момента своего приглашения (так устроена видимость истории в Matrix).
- Синхронизация с Synapse обычная, входящих портов нет.

## Режим админа (необязательно, будьте осторожны)

При `ADMIN_MODE=1` и праве администратора сервера у учётки бота он:

- читает всю историю комнаты через админский API Synapse, в обход видимости «с момента приглашения»;
- для `keep N` без фильтров и `purge older:…` (только срок) **физически стирает** из базы всю историю старше границы (`purge_history`), без пустых остатков. Это необратимо.

Выдать право: `UPDATE users SET admin=1 WHERE name='@genabot:example.org';` в базе Synapse (потом нужен перезапуск Synapse, он кэширует права) или через админ-API. **Админ сервера может всё**: если токен бота попадёт не в те руки, под угрозой весь сервер. Держите `ALLOWED_INVITERS` заполненным и включайте режим только когда он нужен.

Чтобы снять: `ADMIN_MODE=0`, `admin=0` у учётки в базе, перезапуск бота и Synapse.

## Защита от лишнего ввода

Команды старше 2 минут игнорируются (после простоя бот не выполняет «хвост»), не больше 8 команд в минуту от одного пользователя, ограничены длина и число параметров, многострочный ввод отклоняется, `del` удаляет только обычные сообщения. Лимиты настраиваются в `.env`.

## Скорость удаления

Synapse по умолчанию ограничивает частоту событий от одной учётки, и массовое удаление идёт медленно (бот при лимите ждёт и повторяет). Для учётки бота лимит можно снять записью в `ratelimit_override` (`messages_per_second=0`, `burst_count=0`) или через админ-API.
